# 人への引き継ぎ

止まったときに人へ何をどう渡すか。設計書の入口は [README.md](README.md)

判断: 人に引き継ぐのは次の表の理由のときだけ。どの理由にも次にやることを決めておく

表の例は代表だけを書く。全部の例と、セルに書ききれない扱いは [理由ごとの例と扱い](#理由ごとの例と扱い)に書く

| 理由 | 例 | PR | 次にやること |
|---|---|---|---|
| 始められない | 起動ラベルを付けた人が書き込み権限未満。auto-merge が無効 | なし | 設定か Issue か main を修正して、下書きラベルか起動ラベルを付け直す（原因ごとの確かめ先は[始められない](#始められない)） |
| 完了条件が足りない | 下書きの質問が上限に達した。計画、テスト作成、実装、修正の工程のどれかが「完了条件が足りない」と返した | 変更があれば | 完了条件を修正して、下書きラベルか起動ラベルを付け直す |
| 上限に達した | 反復、コスト、時間 | 変更があれば | PR を読んで自分で修正するか、起動ラベルを付け直して続きから進める。下書きで止まったときは下書きラベルを付け直す |
| 判定が決まらない | レポートがスキーマに合わない。レビューの結論と指摘の一覧が食い違う | 変更があれば | PR とレポートを読んで判断する。下書きで止まったときは、Issue を修正して下書きラベルを付け直す |
| 変更が無い | テスト作成の工程が「完了条件はすでに満たされている」と返した。続きから進める実行で、[Claude Code](https://code.claude.com/docs) が何も変えなかった | なし（続きから進めるときは開いている PR のまま） | Issue を閉じるか、完了条件を修正して起動ラベルを付け直す。続きから進めたときは、PR を読んで修正するか、CI を再実行する |
| 自動マージの範囲の外を変える | 依存の定義を変えた。既存のテストを変えた | 変更があれば（自動マージなし）。計画の工程で止まったときは変更が無いので PR は無い | PR を読んでマージする。変更禁止ファイルは人が変えてから起動ラベルを付け直す |
| 提出のあと自動マージまで進めない | 再実行しても CI が失敗した。競合した | 提出済み（続きから進めるときは開いている PR） | PR を修正するか承認する。起動ラベルを付け直せば続きから進める |
| 守りが働いた | 変更禁止ファイルが変わったか、増えた。差分に認証情報の文字列があった | なし（続きから進めるときは開いている PR を更新しない） | 実行のログを読む。認証情報の文字列があったらその認証情報を作り直す |
| 途中で終わった | 下書きか実行のジョブのキャンセル、時間切れ、runner（ジョブを動かすマシン）の不調、Claude Code の認証切れ | なし（提出のジョブで終わったときの扱いは[途中で終わった](#途中で終わった)） | 実行のログを読み、下書きなら下書きラベル、実行なら起動ラベルを付け直す |

理由

- 理由ごとに次にやることが決まっていれば人は判断に時間を使わずに済む
- どの理由にも当てはまらない止まり方を作らない ── 規則に当てはまらないものは「判定が決まらない」、ジョブが失敗したものは「途中で終わった」に入る
- 「提出のあと自動マージまで進めない」は、続きから進める実行では提出の前にも使う（作業のジョブの最初の取り込みと、提出のジョブの push の前）── どちらも開いている PR が自動マージまで進めない状態だから
- 決めた理由で何もせずに終えるときは引き継がない ── 関係ないラベルで起きた、起動ラベルが外れていた、付け直されたラベルの実行に任せた、PR がマージ済み、読むコメントが無い、など。終了処理はこれらを「終えた」の印で見分ける（[run.md の「ワークフローのファイルとジョブ」](run.md#ワークフローのファイルとジョブ)）
- 変更があれば PR にするのは作業を捨てずに人へ渡すため ── 守りが働いたときと、途中で終わったときは、変更を信用できないので PR にしない

## 理由ごとの例と扱い

表に代表だけを書いた理由の全部の例と扱い。表に全部を書いた理由（完了条件が足りない、変更が無い）はここに書かない

### 始められない

下書き

- 下書きラベルのあとに、triage 未満の人が Issue のタイトルか本文を変えた

実行 ── 権限

- 起動ラベルを付けた人が書き込み権限未満

実行 ── リポジトリと App の設定

- auto-merge が無効
- 必須のステータスチェックが無い
- マージキューか、署名付きのコミットの必須がある
- マージの方法が許可されていない
- ワークフローの `GITHUB_TOKEN` の既定が書き込み
- [GitHub Actions](https://docs.github.com/actions) に PR の作成と承認を許す設定（Allow GitHub Actions to create and approve pull requests）が有効
- PR 用トークンを発行できない（App の設定の誤り）

実行 ── 入力と変数

- 作業の action の入力 `test_command` が無い
- 変数 `MERGE_WHILE_YOU_SLEEP_ALLOW_PATHS` が無い

実行 ── 導入先の設定のファイルと準備の step

- 導入先の設定のファイルに helper のコマンド（`apiKeyHelper` など）がある（続きから進めるときは、PR の先頭でも。下書きも同じ理由で止まる）
- 準備の step が git の管理の中のファイルを変えた

実行 ── runner の環境

- sandbox（Claude Code が Bash で起動したコマンドの、読める場所、書ける場所、外への通信先を絞る Claude Code の機能）か、ゲートの隔離（[bubblewrap](https://github.com/containers/bubblewrap)）が起動できない ── 仕組みは [security.md の「ゲートのコマンドを隔離する」](security.md#ゲートのコマンドを隔離する)と[「Claude Code に認証情報を読ませない」](security.md#claude-code-に認証情報を読ませない)
- seccomp フィルタ（Linux でプロセスが使えるシステムコールを絞る仕組み）が無い
- Claude Code をインストールできない（取得に失敗したか、SHA-256 が合わない。下書きも同じ）

実行 ── 承認と下書き

- 下書きの artifact（ワークフローの実行に付けて保存するファイル。ジョブの間とワークフローの間の受け渡しに使う）が期限で消えたか、コメントと合わない
- 承認する完了条件が無い
- 承認の対象かタイトルが起動ラベルのあとに変わった
- 起動ラベルのあとに新しい下書きがある
- 下書きのコメントが、下書き用のワークフローが書いたものと確かめられない
- 下書きの artifact を読めない

実行 ── 基準コミット

- 基準コミットにテストのパターンに合うファイルが無い
- 着手前のゲートが失敗する
- checkout したコミットが基準コミットと違う

原因ごとの確かめ先（表の「次にやること」に加えて）

- sandbox と隔離が起動できないとき: runner の種類（GitHub ホストの Ubuntu）と入力を確かめる
- PR 用トークンを発行できないとき: App のインストール先と秘密鍵を確かめる

### 上限に達した

実行

- 反復
- 同じ指摘
- ゲートの失敗
- テスト作成に戻す回数 ──「テストが間違っている」と、ミューテーションテストの失敗で戻す回数
- コスト
- 時間
- サブスクの利用枠

下書き

- 時間
- コスト

### 判定が決まらない

- レポートがスキーマに合わない
- レビューの結論と指摘の一覧が食い違う
- レビューに渡す差分が20万文字を超えた
- 計画、テスト作成、実装、修正の工程が、決めた理由のほか（その他）で進められないと返した
- Claude Code がほかの理由に当てはまらない終了コードで終わった
- Claude Code がレポートを返さなかった

### 自動マージの範囲の外を変える

- 依存の定義を変えた
- 既存のテストを変えた
- 追加した行に検査を無効にする書き方か外の画像がある
- 続きから進めるときに、PR のブランチの依存の定義が基準コミットと違う
- 計画の工程が変更禁止ファイルを変える見込みと返した（実装の前に止まる）
- 計画の工程が自動マージの範囲の外を変える見込みと返した（PR は作り、自動マージを予約しない）
- git がバイナリとみなしたファイルを変えた
- 削除した行から検査を有効にする書き方（`eslint-enable`、`@ts-check` など）を除いた
- 追加した行に変数 `MERGE_WHILE_YOU_SLEEP_DENY_PATTERNS` の書き方がある

### 提出のあと自動マージまで進めない

- 再実行しても CI が失敗した
- 競合した
- 承認が必要
- 必須のステータスチェックが結果を返さない
- ブランチを最新にし直せない
- 作業の間に人が PR のブランチへ push していた
- 前の実行が予約した自動マージを外せない
- push できない、PR を作れない
- PR が閉じられた
- 提出のあとに PR のブランチへ push された
- 自動マージの予約が外れたか、予約できない
- ブランチを最新にし直す回数が上限に達した、CI の結果を待つ時間の上限に達した
- 競合の解消のあとに競合の印が残っている
- 続きから進めるときに基準コミットの取り込みで競合し、Claude Code に解消させない。次のどれか
  - テストのファイル、固定の除外ファイル、変数 `MERGE_WHILE_YOU_SLEEP_DENY_PATHS` のファイル、CLAUDE.md が `@` で読み込むファイルのどれかで競合した
  - 競合の解消の工程で競合を解消できない
  - 競合したファイルのほかも変えた

### 守りが働いた

- 変更禁止ファイルが変わったか、増えた
- 差分に認証情報の文字列があった
- この実行が追加したコミットのメッセージに、Issue を閉じるキーワードか `@` がある
- 取り込んだコミットが、基準コミットか、PR のブランチの今の先頭の子孫でない
- bundle（作業のジョブが変更を渡す git bundle のファイル）が無いか、取り込めないか、先頭が作業のジョブの出力と違う
- 続きから進めるときに基準コミットを取り込めない（競合したファイルが無いのに取り込みが失敗した）
- Claude Code の呼び出しのあとに止められないプロセスが残った
- ゲートのあとに作業ツリーを戻しても管理の外のファイルが残った
- 作業用のコミットを作れない

### 途中で終わった

- 提出のジョブで終わったときは、PR があればそのリンクと、自動マージを予約したかをコメントに書く
- 予約していれば、CI が成功するとマージされる

## 引き継ぎの方法

判断: Issue に引き継ぎラベルを付け、起動ラベルを付けた人を @メンションしてコメントし、起動ラベルを外す。下書きの工程で止まったときは下書きラベルを付けた人をメンションし、下書きラベルを外す

知らせ方に必要な点は3つ ── 人が気づける（通知が届く）、判断待ちの Issue を一覧で絞り込める、なぜ止まったかと次に何をすればいいかが残る

| 知らせ方 | 気づける | 一覧で絞り込める | 理由が残る |
|---|---|---|---|
| ラベルだけ | 通知のきっかけとして書かれていない | できる | 残らない |
| コメントだけ（@メンションつき） | 通知が届く | できない | 残る |
| アサイン | 通知が届く | できる | 残らない |
| ラベル + コメント（@メンションつき） | 通知が届く | できる | 残る |

根拠: GitHub Docs の [About notifications](https://docs.github.com/en/subscriptions-and-notifications/concepts/about-notifications) に通知が届くきっかけとして「Been assigned to an issue or pull request.」と「Had your username @mentioned.」がある。ラベルを付けたときに通知が届くかはこのページに書かれていない

引き継ぐときにすること

- 引き継ぎラベルを付ける ── 名前は変数 `MERGE_WHILE_YOU_SLEEP_ESCALATION_LABEL` で変えられる
- 起動ラベルを付けた人を @メンションしてコメントする（下書きの工程で止まったときは下書きラベルを付けた人）── 何が起きたか（表の理由のどれか）、根拠（CI が失敗したときは失敗した必須のステータスチェックの名前、どの理由でも実行のログへのリンク）、次にやること
- 起動ラベルを外す ── やり直しが起動ラベルを付ける1つの操作で済む
  - 実行は引き継がずに終わったとき（マージまで進んだとき）も起動ラベルを外す
  - 外すのは、今の起動ラベルを付けた最新の `LabeledEvent` がこの実行の開始より前のものだったときだけ ── 実行の間に人が付け直していたら実行待ちの次の実行のラベルなので外さない。GitHub の API で確かめられないときも外さない
- 下書きの工程で引き継ぐときは下書きラベルを外す ── 外さないと次に権限のある人がコメントしたときに下書きをし直し、上限で止めた意味が無くなる
- 提出のあとに CI が失敗したときも知らせるのは Issue ── PR へのリンクを添える。人が見る場所を1つにする
- 実行の最初に引き継ぎラベルを外す ── やり直したときに前の実行のラベルが残らない
- 途中で終わった実行は終了処理のジョブが引き継ぐ ── ほかのジョブが、決めた終わり方をせずに終わっていたら、終了処理が「途中で終わった」として引き継ぐ

理由

- 3つの点を全部満たすのはラベルとコメントの組み合わせだけ
- @メンションする相手はその Issue を動かすと決めた本人
- ラベルとコメントの操作は全部 `GITHUB_TOKEN` の `issues: write` でできる ── `GITHUB_TOKEN` で起動ラベルを外しても新しい実行は起きない（GitHub Docs の [Triggering a workflow](https://docs.github.com/en/actions/how-tos/write-workflows/choose-when-workflows-run/trigger-a-workflow)）
- コメントを使って関係ない人に通知を送らせない ── コメントは action のコードが決まった形で組み立て、Claude Code が書いた部分の `@` を全角の `＠` に変えてメンションとして機能しないようにする
  - [TAKT](https://github.com/nrslib/takt) も公開するコメントで同じ置き換えをしている（TAKT の src/features/merge/threat-check.ts の `comment.replaceAll('@', '＠')`）
- 工程が「進められない」と返して引き継ぐときは、Claude Code が返した理由をコードブロックに入れて添える ── 人が完了条件を修正する手がかりにする
  - Claude Code の申告なので判定には使わない
  - 投稿する前にほかのコメントと同じく、認証情報の文字列を消し、画像、HTML、リンクを除く（[security.md の「Claude Code に認証情報を読ませない」](security.md#claude-code-に認証情報を読ませない)の「出口で消す」）

確認結果（GitHub ホストの runner `ubuntu-24.04`、Claude Code 2.1.319。回数は各項目に書く）

- `GITHUB_TOKEN`（github-actions[bot]）が書いたコメントの @メンションで通知が届く ── 引き継ぎのコメントでメンションした人に理由が `mention` の通知が届いた（1回）。アサインはしない
